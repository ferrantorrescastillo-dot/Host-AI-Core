- reordena tareas
- prioriza compras urgentes, recursos, personal y producción crítica
- propone soluciones por incidencia
- conserva tareas válidas del planning original
- exige confirmación antes de aplicar cambios

No hace:

- no escribe en base de datos
- no cambia pedidos reales

- no aplica la replanificación automáticamente

Salida principal:

- `nuevo_planning`
- `soluciones`
- `requiere_confirmacion = True` cuando hay cambios
- `aplicado = False`

Filosofía: actuar como segundo jefe de cocina, no como chatbot ni ERP.
